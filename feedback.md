ProcurementManagementApplication

User Review Feedback
Daystar Christian Centre | Procurement Unit

21 August 2026

Each item has been grouped by functional area and tagged by type:

Correction Modification New Feature Removal Question
A. New Request Creation — User Interface
A1 [Removal] Remove the urgency field from the user interface; the expected delivery date
is sufficient.
A2 [Modification] Rename the “Item” field to “Item Description”, and rename the current
“Item Description” field to “Detailed Specification”.
A3 [New Feature] Add the requisitioning department to the new request creation form; it is
currently absent.
A4 [Modification] On the work-tool question (“Is the item requested a work tool?”), add an
in-bracket explanation of what qualifies as a work tool, i.e. computers and accessories,
phones and accessories.
A5 [Removal] Remove the “Recommended Vendor” option from the request creation
interface.
B. User Dashboard & Status Display
B1 [Correction] After a PO is approved, the status on all dashboards should read “Purchase
Order Approved” rather than “Active Bidding”. “Active Bidding” should only apply after RFQ
generation.
B2 [New Feature] Add approval timestamps showing the date each request and each PO
was approved.

C. Approval Workflow&Routing
C1 [Question] How does a user's request currently reach their HOD? The requester's name
should be clearly reflected on the request. — see C2 for the proposed routing change
C2 [New Feature] On the request interface, provide a selectable list of HODs to whom the
request is routed. The list must include the HOF and HHR, since they also function as HODs.
C3 [Modification] Make the approval comment (“provide a reason for approval”) optional
on the HOD approval interface; it is currently required.
C4 [Modification] The HOF should be able to approve requests he generates himself, in the
same way the HOD and HHR can.
C5 [Modification] Requests generated by the PM should be routed to an HOD (selected from
a list) for approval.
C6 [New Feature] Give the HOF and HHR the option to reject or deny a submitted PO. Note:
a PO must not be downloadable without HHR approval.
C7 [Correction] Work-tool requisitions must receive HHR approval at the request stage
before the PM can proceed to RFQ generation.
D. Roles, Permissions & Visibility
D1 [New Feature] Enable the HOF and HHR to view the details and status of all requisitions
— including the justification — to guide their PO approval decisions. They should also be
able to view the associated RFQ.
D2 [Correction] The HHR cannot currently approve work-tool requisitions: clicking “View”
on a work-tool request from the All Requests menu returns “Request Not Found — the
request you're looking for doesn't exist or has been removed.”
D3 [Correction] On the HHR interface, the Requisitions menu should list all requisitions,
including work-tool requisitions; currently, only requests created by the HHR appear there.
D4 [Modification] Vendor approval should be exclusive to the HHR and not the PM;
conversely, the HHR should not be able to add vendors or locations.
E. Notifications
E1 [New Feature] Send an email or SMS notification to the approvers (HOD, HOF, HHR)
whenever a request or PO is submitted and awaiting their approval, so they do not need to
keep opening the app to check for pending items.
F. Vendor Management
F1 [Modification] Under Add New Vendor, make the date of incorporation optional (not
required).

F2 [Modification] Make vendor categories free-typable when adding a new vendor, or give
the PM the ability to add new categories.
G. RFQ Generation
G1 [Correction] After selecting a vendor under Generate RFQ, the vendor details panel
shows a non-functional edit icon. Remove the edit icon and retain only the delete icon.
G2 [Correction] On the downloadable PDF RFQ, the items table should appear before the
evaluation criteria and be presented in table format.
G3 [Correction] On the PDF RFQ, the block from RFQ number down to delivery date should
be well spaced, with the document title at the top in bold (see the attached reference).
H. Purchase Order (PO) Generation
H1 [New Feature] Allow the PM to add new line items at the Generate PO stage, beyond
those pulled from the requisition — vendor invoices often include additional lines such as
logistics and service charges, and the PO stage is where these should be captured. (Currently
only the existing requisition items can be edited.)
H2 [New Feature] Provide fields for discount (which reduces the PO total) and VAT (which
increases the PO total) on the Generate PO page.
H3 [Removal] Remove the evaluation criteria from the Generate PO page; it is only relevant
to RFQ generation.
H4 [New Feature] Allow the PM to edit a PO after submission but before approval.
H5 [Modification] Support attaching multiple vendor quotes on the Generate PO page
(currently only one). The HHR and HOF need to see the selected vendor's quotation
alongside alternative quotations to guide their approval.
H6 [Modification] Make the total amount a required field on the Generate PO page.
H7 [Modification] For service-related requests, the product/service classification should be
made by the PM rather than the requisitioner — or, at minimum, the PM should be able to
override the requisitioner's choice.
H8 [Modification] Service-related requests should not display quantity, unit of measure
(UOM), and unit price at the Generate PO stage and on the final downloaded PDF PO.
H9 [Correction] The location field should display the full address — especially on the PO. It
currently shows only the area name (e.g. “Alimosho”).
H10 [Correction] The PO is not yet downloadable to PDF after all approvals are completed.
I. Post-PO Processes —GRN & Job Completion (NewWorkflow)

I1 [New Feature] The process flow currently ends at PO download. Beside “Download PO”
on the PO page, add “Generate Goods Receipt Note (GRN)” for products and “Generate Job
Completion Form (JCF)” for services, each leading to its own GRN or JCF menu.
I2 [New Feature] GRN: performed by a new role, the Warehouse Manager (WM). The WM
generates the GRN and selects, from lists, the requesting user and the PM as approvers. Both
must approve before the GRN is downloadable; the WM then downloads it to process vendor
payment with Accounts.
I3 [NewFeature] JCF: performed by the PM. The PM generates the JCF and selects, from a
list, the requesting user who must approve it before it is downloadable; the PM then
downloads it to process vendor payment with Accounts.
J. Identified Defects (Bug Fixes)
J1 [Correction] HOD View Request page: there are two approval buttons. The bulk-action
approval on specific items works; the standalone Approve button on the page itself does
nothing.
J2 [Correction] Duplicate of D2 retained for tracking: work-tool request “View” returns
“Request Not Found”. — consolidated under D2/D3 — fix once
J3 [Correction] Duplicate of H10 retained for tracking: approved PO has no PDF download.
— consolidated under H10
